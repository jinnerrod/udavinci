# Introducción

Las **funciones** son **bloques de código** esenciales en la programación que permiten realizar tareas específicas de manera estructurada y modular. Facilitan la reutilización del código, evitando duplicaciones y simplificando el mantenimiento de los programas. Una función puede recibir datos mediante parámetros y devolver resultados, lo que optimiza la eficiencia y claridad del código. Además, ayudan a dividir problemas complejos en partes más manejables, promoviendo la organización y legibilidad. En JavaScript, las funciones pueden ser tradicionales o flecha, adaptándose a diferentes necesidades y estilos de programación.

Su correcta implementación mejora la robustez del **software** y reduce la probabilidad de **errores**. También permiten manejar el ámbito de variables de forma local o global. Las funciones predefinidas y personalizadas amplían las capacidades del lenguaje. En resumen, dominar las funciones es clave para desarrollar aplicaciones dinámicas y eficientes.

Para poder hacer uso de una función se requieren dos **pasos**:

1. Definirla.
2. Invocarla.

# 1. Funciones

Las **funciones** son bloques fundamentales en programación que encapsulan un conjunto de instrucciones para realizar una tarea específica. Estas instrucciones pueden ser invocadas y ejecutadas desde diferentes partes del programa, lo que promueve la reutilización de código y facilita la modularidad. En esencia, las funciones permiten dividir un programa en partes más pequeñas y manejables, lo que simplifica la comprensión, el mantenimiento y la expansión del código.

En la programación, una función puede recibir **parámetros**, realizar operaciones con ellos y devolver un resultado. Este proceso de modularización no solo mejora la organización del código, sino que también facilita la identificación y corrección de errores. Las funciones son esenciales para el desarrollo eficiente de software, ya que proporcionan una manera estructurada de abordar problemas complejos, promoviendo la escritura de código más legible, eficiente y fácil de mantener.

## 1.1 Introducción

Como cualquier lenguaje, JS está conformado por palabras reservadas y sentencias, incluyendo funciones. Al **crear nuevas funciones, estamos aumentando el número de sentencias del lenguaje**, es decir estamos agregando nuevas sentencias al lenguaje, las cuales tenemos a nuestra disposición para elaborar software. Una **función, a** su vez, es considerada un **mini-programa por su propia cuenta**.

Hacer **uso de funciones** no sólo nos ayuda a reducir el trabajo de desarrollo de software, sino también para: Reusar código, reducir complejidad, atrapar errores y mantener actualizaciones.

Al **escribir funciones** es importante considerar las siguientes **recomendaciones**:

> **Importante**
>
> Una función debe realizar una y sólo una tarea
>
> Esta tarea te será útil para diferentes aplicaciones
>
> El código debe estar listo para aplicarle diversas pruebas y validaciones
>
> Diferentes aplicaciones pueden hacer uso de diversas funciones
>
> Organizar nuestras funciones en grupos de funciones relacionadas

---

Una función consta de tres partes, tal como se observa en el siguiente ejemplo:

> **Ejemplo**
>
> // encabezado
>
> function unaFuncion()
>
> {// cuerpo
>
> console.log('magic')
>
> }
>
> // llamada
>
> unaFuncion()

**1. Encabezado**
La palabra reservada function para definir el nombre de la función y paréntesis para recibir parámetros, si es el caso

**2. Cuerpo**
Aquí es donde se resuelve el problema, haciendo uso de algún algoritmo por ejemplo, requiere llaves {} para indicar su inicio y fin

**3. Llamada**
En algún lugar de nuestro programa invocamos la a nuestra función

## 1.2. Interactuando con una función

Existen dos formas de interactuar con una función, ya sea enviando datos a una función, o bien obteniendo resultados desde una función, a continuación, los explicamos.

### a. Enviando datos a una función

Enviar datos a una función es opcional. Ten en cuenta que a las variables/objetos que reciben una función se les conoce como **argumentos**. Mientras que el nombre que reciben los valores enviados (pueden ser también variables/objetos) es **parámetros**.

Al recibir los **parámetros**, la función realiza su tarea (una función también puede recibir una función como parámetro). El número de argumentos declarado define lo que se conoce como n-arity. Por ejemplo, en el siguiente cuadro de más adelante podrás observar que la n-arty es 1, es decir recibe sólo un argumento.

### b. Obteniendo resultados desde una función

Que una función regrese resultados es opcional. A menos que se especifique otra cosa, el valor que regresa es siempre **undefined**.

---

Comúnmente una función regresa un resultado, una variable, un objeto, incluso un array. También puede regresar una función. Por ejemplo, en el siguiente cuadro, se puede observar que la función regresa en valor booleano en respuesta a la pregunta ¿es n un número par?

> **Ejemplo**
>
> // definición
>
> function isEven(n){
>
> if (n%2===0)
>
> return true
>
> else
>
> return false
>
> }
>
> //llamada
>
> console.log(isEven(3))
>
> console.log(isEven(2))


## 1.3. Ámbito

Las **variables**, **objetos**, y **funciones** tienen un ámbito de competencia en nuestros programas y aplicaciones. En JS tenemos principalmente dos ámbitos de competencia: local, global.

**Ámbito global**

Ya que este ámbito puede **contaminarse** con facilidad, debemos tener cuidado de no sobreescribir librerías, objetos, u otras variables.

Toda declaración con var es **hoisted**, lo cual significa que toda declaración se lleva al principio de la función antes de ejecutarla. El intérprete de JS realiza esta tarea.

**Ámbito local**

---

Para esto se recomienda declarar variables, objetos, haciendo uso de la **palabra reservada let**. Toda declaración con let no es hoisted, lo cual significa que no se lleva al principio de la función. Observa el siguiente ejemplo.

> **Ejemplo**
>
> //
>
> // hoisting
>
> //
>
> function hoisting(){
>
> a = 10
>
> let b = 50
>
> }
>
> hoisting()
>
> console.log(a)//ok, hoisted
>
> console.log(b)//error, no hoisted

## 1.5. Funciones flecha

Una de las partes más atractivas del **Ecmascript6** son las funciones flecha. Este tipo de función tiene una nueva y más concisa **sintaxis**, sobre todo cuando en el cuerpo de la función es una sola sentencia; esto se puede hacer de dos maneras:

**1. Enviando datos a una función**
Como podrás apreciar en el ejemplo del cuadro, la palabra reservada function desaparece. Los argumentos son opcionales. En caso de ser requeridos, los recibimos dentro de los paréntesis. Si la función requiere un solo argumento, también los paréntesis se pueden omitir.

**2. Obteniendo resultados desde una función**
El símbolo de flecha es parte e la sintaxis (=>). Después de la flecha colocamos el resultado que va a regresar la función. La palabra reservada return desaparece. En caso de ser necesario, y la función requiere más de una sentencia entonces usamos llaves {} para crear una sentencia compuesta. De ser así, la palabra reservada return es obligatoria.

> **Ejemplo**
>
> /
>
> // Tradicional
>
> //
>
> function multiply(a,b=3) {
>
> return a*b
>
> }
>
> //
>
> // Arrow
>
> //
>
> let arrow= (a,b=3) => a*b
>
> //
>
> //
>
> //
>
> console.log(multiply(2))
>
> console.log(arrow(2))

Las **funciones flecha** son sin duda populares entre los desarrolladores por lo antes expuesto. Sin embargo, fueron creadas para resolver otro problema. En Ecmascript5 cada nueva función tiene su propio this, lo cual tiende a generar errores o al menos confusión. En Ecmascript, las funciones flecha hacen uso del this del contexto más cercano. Ver sección 1.3.

# Recuerda

- Las **funciones** son bloques fundamentales que encapsulan instrucciones para realizar una tarea concreta, favoreciendo la modularidad y la reutilización del código. Permiten dividir programas complejos en partes más pequeñas y manejables. Esto mejora la legibilidad, el mantenimiento y la escalabilidad del software.
- Una **función** se compone de **encabezado**, **cuerpo** y **llamada**, y puede recibir parámetros y devolver resultados, aunque ambos aspectos son opcionales. Definir funciones con una única responsabilidad facilita las pruebas y la detección de errores. Una correcta organización de funciones reduce la complejidad del desarrollo.
- El **ámbito** determina la visibilidad de variables y funciones dentro del programa, siendo principalmente global o local. El uso adecuado de let frente a var ayuda a evitar problemas de hoisting y contaminación del ámbito global. Trabajar en ámbitos locales aporta mayor seguridad y control al código.
- **JavaScript** ofrece funciones predefinidas y nuevas sintaxis como las funciones flecha, que simplifican la escritura y el uso del contexto this. Las funciones flecha permiten un código más conciso y claro en muchos casos. Su uso adecuado contribuye a un desarrollo más eficiente y moderno.
