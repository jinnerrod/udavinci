# 1. ¿Qué es Hadoop? Relación con Big Data

**Hadoop** es un **framework de software de Apache Software Foundation** que se utiliza para almacenar y procesar Big Data. Tiene dos componentes principales; Hadoop Distributed File System (HDFS), su sistema de almacenamiento y MapReduce, que es su marco de procesamiento de datos. Hadoop tiene la capacidad de administrar grandes conjuntos de datos distribuyendo el conjunto de datos en fragmentos más pequeños en múltiples máquinas y realizando cálculos paralelos en él.

Hadoop tiene un gran potencial dentro del contexto Big Data, que facilita el análisis de grandes cantidades de datos. Por eso, Hadoop es un componente esencial de la industria de Big Data, ya que proporciona la capa de almacenamiento más confiable, HDFS, que puede escalar masivamente. Empresas como Yahoo y Facebook utilizan HDFS para almacenar sus datos.

HDFS tiene una arquitectura maestro-esclavo donde el nodo maestro se llama NameNode y el nodo esclavo se llama DataNode. El NameNode y sus DataNodes forman un clúster. NameNode actúa como un instructor de DataNode mientras que DataNodes almacenan los datos reales.

Hay otro componente de **Hadoop** conocido como **YARN**. El objetivo de Yarn es administrar los recursos y programar y monitorizar trabajos en Hadoop. Yarn tiene dos componentes principales, Resource Manager y Node Manager. El administrador de recursos tiene la autoridad para asignar recursos a varias aplicaciones que se ejecutan en un clúster. El administrador de nodos es responsable del uso de los recursos (CPU, memoria, disco) y reportarlo al administrador de **recursos**.

## 1.1. Ventajas de Hadoop

1. **Económico**

   Hadoop es un producto Apache de código abierto, por lo que es software gratuito. Tiene un costo de hardware asociado. Es rentable ya que utiliza hardware básico que son máquinas baratas para almacenar sus conjuntos de datos y no una máquina especializada.

2. **Escalable**

   Hadoop distribuye grandes conjuntos de datos en varias máquinas de un clúster. Se pueden agregar fácilmente nuevas máquinas a los nodos de un clúster y se pueden escalar a miles de nodos que almacenan miles de terabytes de datos.

3. **Tolerancia a fallos**

   Hadoop, de forma predeterminada, almacena 3 réplicas de datos en los nodos de un clúster. Entonces, si algún nodo deja de funcionar, los datos se pueden recuperar de otros nodos.

4. **Rapidez**

   Dado que Hadoop procesa datos distribuidos en paralelo, puede procesar grandes conjuntos de datos mucho más rápido que los sistemas tradicionales. Es muy adecuado para el procesamiento de datos por lotes.

5. **Flexibilidad**

   Hadoop puede almacenar datos estructurados, semiestructurados y no estructurados. Puede aceptar datos en forma de archivo de texto, imágenes, archivos CSV, archivos XML, correos electrónicos, etc.

6. **Localidad de los datos**

   Tradicionalmente, para procesar los datos, los datos se obtenían de la ubicación en la que están almacenados, a la ubicación donde se envía la solicitud; sin embargo, en Hadoop, la aplicación de procesamiento va a la ubicación de los datos para realizar el cálculo. Esto reduce la demora en el procesamiento de datos.

7. **Compatibilidad**

   La mayoría de las herramientas de big data emergentes se pueden integrar fácilmente con Hadoop, como Spark. Utilizan Hadoop como plataforma de almacenamiento y funcionan como su sistema de procesamiento.

## 1.2. Métodos de implementación de Hadoop

##### Modo autónomo

Es el modo predeterminado de configuración de Hadoop. En su lugar, no usa hdfs, usa un sistema de archivos local tanto para la entrada como para la salida. Es útil para depurar y probar.

##### Modo pseudodistribuido

También se denomina clúster de un solo nodo en el que tanto NameNode como DataNode residen en la misma máquina. Todos los dominios se ejecutan en la misma máquina en este modo. Produce un clúster en pleno funcionamiento en una sola máquina.

##### Modo completamente distribuido

Hadoop se ejecuta en varios nodos en los que hay nodos separados para dominios maestro y esclavo. Los datos se distribuyen entre un grupo de máquinas que proporcionan un entorno de producción.

# 3. Sistema de archivos HDFS

El **sistema de archivos distribuido de Hadoop (HDFS)** es un sistema de archivos distribuido diseñado para ejecutarse en hardware básico. Tiene muchas similitudes con los sistemas de archivos distribuidos existentes.

Sin embargo, las diferencias con otros sistemas de archivos distribuidos son significativas:

- HDFS es altamente tolerante a fallos y está diseñado para implementarse en hardware de bajo coste.
- Proporciona acceso de alto rendimiento a los datos de la aplicación y es adecuado para aplicaciones que tienen grandes conjuntos de datos.
- Relaja algunos requisitos POSIX para permitir el acceso de transmisión a los datos del sistema de archivos.
- HDFS se creó originalmente como infraestructura para el proyecto del motor de búsqueda web Apache Nutch, en la actualidad, es un subproyecto de Apache Hadoop.

## 3.1. NameNode y DataNodes

HDFS tiene una arquitectura maestro/esclavo. Un **clúster HDFS** consta de un solo **NameNode**, un servidor maestro que administra el espacio de nombres del sistema de archivos y regula el acceso a los archivos por parte de los clientes. Además, hay varios DataNodes, generalmente uno por nodo en el clúster, que administran el almacenamiento adjunto a los nodos en los que se ejecutan.

HDFS expone un espacio de nombres del sistema de archivos y permite que los datos del usuario se almacenen en archivos.

Internamente, un archivo se divide en uno o más bloques y estos bloques se almacenan en un conjunto de DataNodes. NameNode ejecuta operaciones de espacio de nombres del sistema de archivos, como abrir, cerrar y cambiar el nombre de archivos y directorios. También determina la asignación de bloques a DataNodes. Los DataNodes son responsables de atender las solicitudes de lectura y escritura de los clientes del sistema de archivos.

# 4. MapReduce con Hadoop

**MapReduce** es una técnica de **procesamiento** y un **modelo de programa** para computación distribuida basada en java. El algoritmo MapReduce contiene dos tareas importantes: Map y Reduce.

Map toma un conjunto de datos y los convierte en otro conjunto de datos, donde los elementos individuales se dividen en tuplas (pares clave / valor). En segundo lugar, la tarea Reduce toma la salida de un mapa como entrada y combina esas tuplas de datos en un conjunto más pequeño de tuplas. Como implica la secuencia del nombre MapReduce, la tarea de reducción siempre se realiza después del trabajo de mapeo.

La principal ventaja de MapReduce es que es fácil escalar el procesamiento de datos en múltiples nodos informáticos. En el modelo MapReduce, las primitivas de procesamiento de datos se denominan mapeadores y reductores. A veces, descomponer una aplicación de procesamiento de datos en mapeadores y reductores no es trivial. Pero, una vez que escribimos una aplicación en el formulario MapReduce, escalar la aplicación para que se ejecute en cientos, miles o incluso decenas de miles de máquinas en un clúster es simplemente un cambio de configuración. Esta sencilla escalabilidad es lo que ha atraído a muchos programadores a utilizar el modelo MapReduce.

---

En general, el algoritmo de MapReduce se basa en enviar la computadora a donde están los datos.

El programa MapReduce se ejecuta en tres etapas:

- **Etapa de mapa.**
- **Etapa de barajar (shuffle).**
- **Etapa de reducción.**

Etapa del mapa: el trabajo del mapa o del asignador es procesar los datos de entrada. Generalmente, los datos de entrada están en forma de archivo o directorio y se almacenan en el sistema de archivos Hadoop (HDFS). El archivo de entrada se pasa a la función del asignador línea por línea. El asignador procesa los datos y crea varios fragmentos pequeños de datos.

Etapa Reducir: esta etapa es la combinación de la etapa Shuffle y la etapa Reducir. El trabajo del Reductor es procesar los datos que provienen del mapeador. Después del procesamiento, produce un nuevo conjunto de salida, que se almacenará en HDFS.

Durante un trabajo de MapReduce, Hadoop envía las tareas de Map y Reduce a los servidores apropiados en el clúster.

El framework gestiona todos los detalles del paso de datos, como la emisión de tareas, la verificación de la finalización de la tarea y la copia de datos en el clúster entre los nodos.

La mayor parte de la informática tiene lugar en nodos con datos en discos locales que reducen el tráfico de la red.

Después de completar las tareas dadas, el clúster recopila y reduce los datos para formar un resultado apropiado y los envía de vuelta al servidor Hadoop.


## 4.1. Ejemplo: Un contador de letras

WordCount es una aplicación simple que cuenta el número de ocurrencias de cada palabra en un conjunto de entrada dado.

Esto funciona con una instalación de Hadoop local independiente, pseudodistribuida o completamente distribuida (Configuración de nodo único).

**Código fuente**

```java
import java.io.IOException;
import java.util.StringTokenizer;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IntWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;

public class WordCount {

    public static class TokenizerMapper
        extends Mapper<Object, Text, Text, IntWritable> {

        private final static IntWritable one = new IntWritable(1);
        private Text word = new Text();

        public void map(Object key, Text value, Context context
        ) throws IOException, InterruptedException {
            StringTokenizer itr = new StringTokenizer(value.toString());
            while (itr.hasMoreTokens()) {
                word.set(itr.nextToken());
                context.write(word, one);
            }
        }
    }

    public static class IntSumReducer
        extends Reducer<Text, IntWritable, Text, IntWritable> {
        private IntWritable result = new IntWritable();

        public void reduce(Text key, Iterable<IntWritable> values,
                           Context context
        ) throws IOException, InterruptedException {
            int sum = 0;
            for (IntWritable val : values) {
                sum += val.get();
            }
            result.set(sum);
            context.write(key, result);
        }
    }

    public static void main(String[] args) throws Exception {
        Configuration conf = new Configuration();
        Job job = Job.getInstance(conf, "recuento de palabras");
        job.setJarByClass(WordCount.class);
        job.setMapperClass(TokenizerMapper.class);
        job.setCombinerClass(IntSumReducer.class);
        job.setReducerClass(IntSumReducer.class);
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(IntWritable.class);
        FileInputFormat.addInputPath(job, new Path(args[0]));
        FileOutputFormat.setOutputPath(job, new Path(args[1]));
        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }
}
```

# 5. Apache Hive

**Apache Hive** es un sistema de almacenamiento de datos que está diseñado para funcionar en **Hadoop**. Se utiliza para consultar y administrar grandes conjuntos de datos que residen en almacenamiento distribuido. Antes de convertirse en un proyecto de código abierto de Apache Hadoop, Hive se originó en Facebook. Proporciona un mecanismo para proyectar la estructura en los datos en Hadoop y para consultar esos datos utilizando un lenguaje similar a SQL llamado HiveQL (HQL).

> **Hive se usa bastante porque las tablas de Hive son similares a las tablas de una base de datos relacional.**
>
> **Muchos usuarios pueden consultar los datos simultáneamente mediante Hive-QL.**

Hive define un lenguaje de consulta simple similar a SQL para consultar y administrar grandes conjuntos de datos llamado Hive-QL (HQL). Es fácil de usar si se está familiarizado con el lenguaje SQL.

Los usos de Hive son los siguientes:

- El almacenamiento distribuido de Apache Hive.
- Hive proporciona herramientas para facilitar la extracción, transformación y carga de datos (ETL).
- Proporciona la estructura en una gran variedad de formatos de datos.
- Al usar Hive, podemos acceder a los archivos almacenados en el Sistema de archivos distribuido de Hadoop (HDFS se utiliza para consultar y administrar grandes conjuntos de datos que están almacenados allí) o en otros sistemas de almacenamiento de datos como Apache HBase.

---

También tiene **limitaciones**:

- Hive no está diseñado para el procesamiento de transacciones en línea (OLTP), solo se utiliza para el procesamiento analítico en línea.
- Hive admite sobrescribir o capturar datos, pero no actualiza ni elimina.
- En Hive, las subconsultas no son compatibles.

Componentes de **Hive**:

- **Metastore**: Hive almacena el esquema de las tablas de Hive en un Metastore de Hive. Metastore se utiliza para almacenar toda la información sobre las tablas y particiones que se encuentran en el almacén. De forma predeterminada, el Metastore se ejecuta en el mismo proceso que el servicio Hive y el Metastore predeterminado es DerBy Database.
- **SerDe**: Serializer, Deserializer da instrucciones a Hive sobre cómo procesar un registro.

# 6. Apache Hue

Hue es una interfaz web de código abierto para **analizar datos** con cualquier framework basado en Apache Hadoop o aplicaciones del ecosistema Hadoop. Hue proporciona interfaces y UI para interactuar con Hadoop Distributed File System (HDFS), aplicaciones MapReduce, flujos de trabajo Oozie, consultas Hive e Impala, etc. Entonces, Hue es una interfaz de usuario web que facilita el uso del ecosistema Hadoop sin interactuar con el indicador de línea de comandos para la mayoría de las actividades comunes. Hue es desarrollado y de código abierto por Cloudera.

Hue proporciona muchas características e interfaces web para una gran cantidad de servicios, algunos de los cuales son los siguientes:

- Explorador de archivos HDFS.
- Diseñador de trabajos y navegador.
- Acceso a la API de Hadoop.
- Acceso a Hadoop Shell.
- Administrador de usuarios.
- Editor de consultas de Hive.
- Editor de consultas de Pig.
- Interfaz Oozie para flujos de trabajo.
- Interfaz para búsquedas SOLR.

Esta es la razón por la que Hue se usa mucho en las instalaciones de **Hadoop Cluster**, combina casi todas las funciones básicas requeridas y lo hace fácil de usar para personas que no están familiarizadas con las herramientas de línea de comandos de cada uno de estos servicios.

## 7.1. Crear RDD y Data Frames

**RDD** son las siglas de **Resilient Distributed Dataset**. Es un contenedor de datos en memoria. Es resistente porque es tolerante a fallos: se crean y mantienen copias redundantes de RDD. Se distribuye a través de múltiples nodos en múltiples particiones. Se puede calibrar el factor de replicación y el número de particiones para calibrarlo de acuerdo con la capacidad de su hardware y las necesidades de la aplicación.

Así es como creamos un RDD a partir de un archivo de texto, imprimimos el contenido y contamos el número de líneas. El separador de carpetas en el nombre del archivo debe ser una barra inclinada '/' y no el estándar de Windows '\'.

Para crear RDD con Scala, lanzamos los siguientes comandos:

```
> val empRDD = sc.textFile("C:/Users/User/Documents/Work/Data/Employees.txt")
> empRDD.count()
> empRDD.collect()
```

## 7.3. Leer y escribir archivos en HDFS

En los ejemplos anteriores, hemos leído y escrito el archivo en el **sistema de archivos local**. Pero podemos hacer lo mismo en HDFS, es decir, leer desde HDFS y escribir en HDFS o leer desde Local FS y escribir en HDFS o viceversa. Para acceder a **HDFS** mientras leemos o escribimos un archivo, hay que modificar ligeramente el comando.

Al especificar la ubicación de origen / destino, mencionamos el espacio de nombres HDFS.

```
> spark.read.json("hdfs://<Hadoop's default FS/<Directory>/<file.json>")
```

Si no sabemos cuál es el FS predeterminado de Hadoop, ejecutamos el siguiente comando para consultar la configuración de Hadoop.

```
> hdfs getconf -confkey fs.defaultFS
```

# Recuerda

- **Hadoop**: Tiene un gran potencial dentro del contexto Big Data, que **facilita** el **análisis** de grandes cantidades de datos.

- **Sistema de archivos distribuido**: El sistema de archivos distribuido de Hadoop (**HDFS**) es un sistema de archivos distribuido diseñado para **ejecutarse** en **hardware básico**.

- **MapReduce**: Es una **técnica de procesamiento** y un modelo de programa para **computación distribuida** basada en java. El algoritmo MapReduce contiene dos tareas importantes: Map y Reduce.

- **Apache Hive**: Es un **sistema de almacenamiento** de datos que está diseñado para funcionar en Hadoop. Se utiliza para consultar y administrar grandes conjuntos de datos que residen en **almacenamiento distribuido**.

- **Hue**: Es una **interfaz web de código abierto** para analizar datos con cualquier framework basado en Apache Hadoop o aplicaciones del ecosistema Hadoop.

- **Apache Spark**: Es un marco de computación en **clúster de código abierto**. Spark se utiliza principalmente para procesar grandes volúmenes de datos.
